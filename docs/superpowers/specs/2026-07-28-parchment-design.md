# Parchment 设计文档

日期：2026-07-28
状态：已与用户确认通过
项目名：Parchment（暂用名；候选名 entropy cut，最终命名后续再定）

## 1. 产品定位

为科研工作者做的、能吃下 AI 时代混合内容（文字 + 图片 + HTML artifact + 文献引用 + 流程图 + 公式）的极简网页笔记本。单用户、自部署（fly.io），开源供他人自部一份。

三条产品原则（一切功能取舍的标尺）：

1. **轻量级压倒一切** —— 不做的功能比做的功能重要。
2. **打开即写、零摩擦** —— 才能养成记笔记习惯。
3. **自用优先** —— 架构上留推广余地（自部署友好），但不为多用户妥协。

## 2. 已确认的关键决策

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 组织模型 | 日期时间流为主干 + 条目打项目标签 + 按项目过滤视图 | 记录时零成本（顺着今天写），回看时有结构（抽项目时间线）；契合多项目并行的科研工作方式 |
| 部署模式 | 每人自部一份，无账号系统，单访问密码 | 最轻；数据完全自持 |
| 文献引用深度 | 链接自动变引用卡片，不做文献库管理、不做 BibTeX 导出 | 「把链接放在那儿就行」；库管理是 Zotero 的事 |
| HTML 粘贴 | 智能自动判断：内容型转可编辑正文，交互型转沙箱嵌入块，不弹窗询问 | 用户偶尔要改文字（需可编辑），又要保真渲染 artifact；自动做对的事，符合极简 |
| 底层格式 | 编辑器文档模型为 HTML 原生（ProseMirror），Markdown 仅作输入快捷方式 | 为「粘贴 AI HTML 原生兼容」服务；用户 Markdown 手感通过输入规则保留 |
| 技术路线 | 单容器小服务器 + 网页编辑器（路线 A），不做 local-first 同步 | 同步冲突处理工程量翻倍，违背轻量原则；断网风险用本地草稿缓冲兜底 |

## 3. 产品形态

### 3.1 主视图：时间流

- 打开网址（首次输访问密码，之后 cookie 记住）即是「今天」，光标就位，直接打字。
- 聊天式布局：今天在底部（视口默认落在这里），向上滚动加载昨天、前天……（按需分页加载历史）。「一直续下去」= 永远在底部追加。
- 每天一个日期标头，下挂当天的若干**条目（entry）**。新建条目：快捷键或日期旁的 + 按钮。
- 条目是独立的编辑区块，各自保存；一天内条目可拖动排序。

### 3.2 项目标签与过滤视图

- 在条目内输入 `#项目名` 即建即打标；一个条目可打多个标签。
- 左侧极窄边栏（可收起）：项目列表（带颜色圆点）+ 搜索框。
- 点击项目 → 视图变为该项目的专属时间线（排列方向与主视图一致：旧在上、新在下，底部是最新）。再点回「全部」恢复时间流。
- 项目可归档（从边栏隐去，条目保留）。

### 3.3 界面克制

- 无常驻工具栏。选中文字浮出小格式条（粗体、斜体、链接、行内代码、高亮）。
- 输入 `/` 呼出插入菜单：图片、文献引用、Mermaid 流程图、表格、代码块、HTML 嵌入块、待办清单、分割线。
- 亮/暗主题跟随系统，可手动切换。
- 桌面优先；响应式布局保证手机能看、能轻度编辑。

## 4. 编辑体验

### 4.1 Markdown 快捷输入（Typora 手感）

`# ` 标题、`- ` 列表、`1. ` 有序列表、`[] ` 待办、`> ` 引用、`**x**` 粗体、`*x*` 斜体、`` `x` `` 行内代码、``` 代码块、`---` 分割线、`$...$` 行内公式、`$$` 块公式、```mermaid 流程图。即打即渲染。

### 4.2 图片

- 粘贴（截图 Ctrl+V）或拖拽文件 → 立即上传服务器，服务器按 `/data/images/YYYY/MM/<内容hash>.<ext>` 归档，返回 URL 插入文档。
- 上传中显示占位；失败保留本地预览并提示重试。
- 文中拖拽图片边角自由缩放（存储宽度百分比）；点击图片放大查看原图。
- 存原图不压缩（科研图保真）；同内容 hash 去重。

### 4.3 文献引用卡片

- 粘贴 DOI / arXiv / PubMed / 普通期刊 URL：识别为文献链接时，后端抓取元数据 → 渲染为紧凑引用卡片（作者、年份、标题、期刊/来源），点击跳原文。
- 元数据来源链：DOI → Crossref API；arXiv → arXiv API；PubMed → NCBI API；其他 URL → 抓页面 `<title>` 和 meta 标签。
- 抓取异步进行，先插入普通链接，成功后升级为卡片；失败则保持普通链接，绝不阻塞输入。
- 元数据缓存入库（citations 表），同链接二次引用不重复抓取。

### 4.4 AI HTML 粘贴（招牌功能）

粘贴剪贴板含 HTML 时自动判断：

- **内容型**（仅含标题、段落、列表、表格、图片、基础行内样式）→ 转换为编辑器原生节点，完全可编辑。
- **交互/复杂型**（含 `<script>`、`<style>` 块、`<canvas>`、`<iframe>`、SVG 动画、内联事件等）→ 整体存为**沙箱嵌入块**：`<iframe sandbox="allow-scripts" srcdoc=...>` 原样渲染，不给 same-origin 权限（不能访问笔记数据）。嵌入块可调高度、可折叠、可删除、可查看/编辑源码。
- 不弹窗询问。误判兜底：嵌入块菜单提供「转为正文」，正文粘贴后 toast 提供「改为嵌入块」撤销入口。
- `/嵌入` 命令支持手动粘贴 HTML 源码创建嵌入块。

### 4.5 流程图与公式

- ```mermaid 代码块实时渲染；点击图形切回源码编辑。渲染失败显示错误与源码，不吞内容。
- KaTeX 渲染 `$...$` 与 `$$...$$`。

### 4.6 自动保存

- 停笔 1 秒防抖保存（按条目 PATCH）；右上角状态圆点（已保存/保存中/离线）。
- localStorage 草稿缓冲：每次编辑先写本地，保存成功后清除；断网/服务器故障时本地保留，恢复后自动补传。
- 多标签页并发：乐观锁（updated_at 版本比对），冲突时提示刷新取最新（单用户场景足够）。

### 4.7 搜索

- 边栏搜索框全文搜索所有条目，SQLite FTS5 trigram tokenizer（中英文子串均可搜）。
- 结果按时间倒序，显示条目摘要与所属日期/项目，点击跳转定位。

## 5. 数据模型（SQLite）

```sql
entries        (id, day TEXT, position INTEGER, content TEXT/*ProseMirror JSON*/,
                text TEXT/*纯文本抽取供搜索*/, created_at, updated_at,
                deleted_at TEXT/*软删除标记，NULL=正常*/)
projects       (id, name UNIQUE, color, archived INTEGER DEFAULT 0, created_at)
entry_projects (entry_id, project_id, PRIMARY KEY(entry_id, project_id))
citations      (id, url UNIQUE, doi, title, authors, year, venue, fetched_at)
entries_fts    (FTS5 trigram, content=entries, 索引 text 列)
```

图片存文件系统 `/data/images/YYYY/MM/<hash>.<ext>`，文档内以 URL 引用，不入库。

## 6. 后端 API（Hono, Node.js）

```
POST   /api/auth              密码换 HttpOnly session cookie
GET    /api/entries?before=&project=&q=   分页拉取（时间流/项目过滤/搜索）
POST   /api/entries           新建条目
PATCH  /api/entries/:id       保存内容/标签/排序（带版本号乐观锁）
DELETE /api/entries/:id       删除条目（软删除，deleted_at 标记，不物理删除）
GET    /api/projects          项目列表
PATCH  /api/projects/:id      改名/改色/归档
POST   /api/images            上传图片，返回 URL
GET    /images/...            静态图片服务
POST   /api/cite              提交 URL，返回/抓取引用元数据
GET    /api/export            全库导出 Markdown + 图片 zip
```

所有 `/api/*` 与 `/images/*` 需通过 session 认证。

## 7. 技术栈与部署

- **后端**：Node.js + Hono + better-sqlite3。单进程。
- **前端**：Vite + React + TipTap（ProseMirror）。KaTeX、Mermaid 按需懒加载（不进首屏包）。
- **认证**：环境变量 `ACCESS_PASSWORD`，登录换 HttpOnly cookie；HTTPS 由 fly.io 平台提供。
- **部署**：单 Dockerfile（前端构建产物由后端静态托管）；fly volume 挂 `/data`（SQLite + 图片全在内）。**备份 = 拷走 /data 文件夹**。
- **数据导出**：一键导出全部笔记为 Markdown 文件（按日期组织）+ 图片文件夹，zip 下载。嵌入块导出为 HTML 文件旁挂。防锁定，必须有。
- **开源推广**：仓库附「fly launch 一键部署」README，他人自部自用。

## 8. 错误处理原则

- 保存失败：明确的界面提示 + 本地缓冲保留 + 指数退避自动重试。
- 引用抓取失败：降级普通链接，不打断书写。
- Mermaid/公式语法错误：显示错误与源码，不吞内容。
- 图片上传失败：本地预览保留 + 重试按钮。
- 删除均为软删除，杜绝误删丢数据。

## 9. 测试策略

- 后端：API 集成测试（认证、条目 CRUD、乐观锁冲突、图片上传归档、引用抓取降级、FTS 中英文搜索、导出）。
- 前端：核心交互组件测试——HTML 粘贴分类（内容型/交互型判定规则表驱动）、Markdown 输入规则、图片缩放持久化、自动保存防抖与离线缓冲。
- 引用抓取对外部 API 一律 mock；提供录制的真实响应样本。

## 10. 明确不做（v1 范围外）

多用户/账号系统、协作编辑、手机 App、文件夹层级、双链/图谱、插件系统、Zotero 同步、BibTeX 导出、全局文献库页、local-first 离线编辑、版本历史。

## 11. 验收标准

1. 打开到能打字 ≤ 1 秒（fly.io 冷启动除外）。
2. 粘贴 AI 生成的内容型 HTML 段落 → 变为可编辑正文，改字即改。
3. 粘贴带脚本的交互式 artifact → 沙箱嵌入块原样渲染、能动、可调高度。
4. 粘 arXiv/DOI 链接 → 数秒内出引用卡片；断网时保持普通链接。
5. 图片 Ctrl+V 即插入，拖角缩放，刷新后大小保持，服务器按年月归档。
6. 断网继续打字不丢字，恢复后自动补存。
7. 中文与英文关键词均能搜到目标条目。
8. `#标签` 打标后，点击边栏项目可抽出该项目完整时间线。
9. 一键导出得到可读的 Markdown + 图片 zip。
